## What the control told us

The two outright control misses (E1, T4) are precisely the two questions
whose keys live in the docs rather than the tool: NPC damage-profile
weights, and the burst/beacon stacking split. The model's memory is
confidently wrong exactly where the trap catalogue says it is — T4 control
reproduced the roadmap's own original error ("env effects are
stacking-exempt") *and* added an inversion of Wolf-Rayet's effects.
Smaller control dings were the same genre: invented extender stacking
(T5), rig/low-slot confusion (E5), hedged tick behavior (E2).

Equally interesting: the control scored 69%, not 30% — because the **tool
surface itself carries discipline**. Every control run that imported a fit
caught the PG-illegal battery fits (the `problems` list is in every
summary), and unit-suffixed panel keys kept units straight. The MCP's
design rules are earning their keep independently of the skill.

## Notes for the next generation

- Token cost of the skill arm: ~46k tokens/question vs ~38k control — the
  ~8k delta is the router + one or two references read per question. In a
  real chat that loads once per conversation, not per question.
- The eval prompt hands the subject a clean tool manual; a real chat's MCP
  schemas are terser. The control's 69% is therefore a *ceiling* for
  no-skill performance, not a floor — memory-only answers (no engine)
  would have failed every E question outright.
- Candidates for generation 2: overheating deltas, ancillary reload
  windows (ASB/AAR sustain math), a T4-style question on Pulsar armor
  maluses vs enemy ewar (bonus/penalty chain separation), mutated modules
  once modeled, and a question whose correct answer is "the engine cannot
  compute this" (pure unmodeled discipline).
