# Eval generation 10 — the layer-1 server, measured (2026-08-19)

A rerun of gen-9's **layer-1 arm only** — the same five subjects, the same five
opening questions, verbatim — with the `eve-sde` MCP server live. Gen-9 is the
baseline; this is the paired treatment.

Same three-turn shape: T1 the layer-1 question, T2 a follow-up on the topic,
T3 the unrelated Stabber-align question. **T3 is pure layer 2 for every
subject, so the SDE server cannot touch it — it is the control arm**, and it
is what tells us how much of any movement is just run-to-run variance.

## The server was broken until this run

Worth recording first: gen-9 called itself a baseline "pending a run with the
server live", but the server could not have run at all. It imported the `mcp`
SDK, which exists only in layer 2's virtualenv, while `.mcp.json` launched it
with a bare `python3` — `CONNECTION_CLOSED` on every start. `test_server.py`
missed it by launching via `sys.executable`, so under the virtualenv every
assertion passed against a server that could not start in deployment. Fixed in
`e5f2025`: a stdlib-only stdio implementation (`sde/mcp/_stdio.py`) so layer 1
needs nothing but `python3`, and the test now reads its launch command out of
`.mcp.json` so the two cannot drift again.

## Reading this honestly

**The headline is not a win.** Overall, paired across every comparable turn:
**-2%**. That is nothing.

The tempting number is the opening question — five identical pure-layer-1
questions, **-33% billed and 9.6 → 7.0 rounds**. But the control arm is the
check on that, and the control moved **+30%** on turns where the server is not
even reachable. A treatment effect of -21% (all layer-1 turns) sitting beside a
+30% control swing is **not separable from run-to-run variance at n=5**. This
run cannot claim a cost saving, and gen-9's framing of "the number to beat"
turns out to have been the wrong question to ask of five samples.

**What did change, unambiguously, is the mechanism.** Shell round-trips for
raw SQL went from **49 calls to 4**, replaced by **27 server calls** (23
`query`, 4 `attrs`). Four of five subjects used no shell at all. Skill loads
and ToolSearch calls held flat (8 → 9, 10 → 12), so this is not discovery
overhead moving around — layer 1 genuinely stopped being answered by
hand-written SQL in a subprocess.

**The variance has a shape.** The server compresses the worst cases and costs a
round on the cheapest ones:

- where the baseline flailed, it wins big — recharge 14 rounds → 4 (**-70%**),
  cargo 14 → 9 (**-46%**), ore 9 → 6 (**-45%**)
- where the baseline was already efficient, it loses — blueprint 5 → 8
  (**+54%**), universe 6 → 8 (**+35%**)

Since cost concentrates in the bad cases, compressing them is the right
direction even at n=5. But it is a claim about the tail, not the mean, and this
sample cannot size it.

## The finding that matters most: batching is unused

`query` was built to take **many statements per round**, on the reasoning that
the round is the unit of cost. Measured across this run:

- **22 of 24 `query` calls sent exactly one statement.** Mean 1.1.

So the entire premise the tool was designed around is not being exercised. The
-33% on opening questions comes from deleting the shell round-trip, not from
batching — the batching lever is still fully untapped.

This is the same lesson as every earlier placement experiment, one level down:
prose in a docstring saying "batch your queries" does not change behavior; the
tool's **shape** does. `query(sql: str)` takes a string, and a string invites
one statement. A shape like `query(statements: list[str])` makes a single query
the awkward case and multiples the natural one. That is the next experiment,
and it is a strictly better one than re-running these fifteen turns.

## Caveats

- **n=5 subjects, 13 paired turns.** The control arm's +30% is the honest error
  bar. Nothing here is significant.
- Effort: Agent + SendMessage inherits session effort rather than pinning
  medium, same as gen-9 — so both arms are shifted the same direction and the
  pairing still holds.
- The prompt preamble changed by one clause, naming both MCP servers instead of
  one. That was necessary to make the server reachable and it is what a real
  session looks like, but it is a difference between the arms.
- One subject's T3 relay arrived mid-T2 and it answered both in one turn (same
  artifact as gen-9's cross-layer subject); that turn is unpairable and
  excluded.
- Not graded for accuracy. One incidental observation: the gen-10 cargo subject
  spent its extra rounds catching that the fitted afterburner adds 5,000,000 kg
  of mass while active — a better answer than the baseline gave, at higher cost.
  Cost and quality are not independent here, which is a further reason not to
  read the totals as a clean cost comparison.
