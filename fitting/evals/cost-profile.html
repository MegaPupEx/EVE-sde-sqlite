The two numbers, and why one looks alarming

Layer-1-era questions were reported as context; the layer-2 chart below reports billed. Measured the same way, the gap is far smaller than the headline suggests — and the growth is tool rounds, not documentation.

Context grew 20%. Billed grew 3.4×. The difference is entirely tool rounds — ~4 per question in the layer-1 era against ~10 now. Every extra round re-reads ~45k of context.

Tokens billed per answered question

Input + cache writes + output, deduplicated per API request. The two 3-turn runs amortise their cold start over three questions; the single-turn runs pay it every time.

The cold start is the cost. A single-turn session costs more per question than a three-turn one, because the skill read, tool schemas and fit setup are paid once per session, not once per answer. Follow-up questions are the cheap ones — the resident-fit design is doing its job.

Where every token goes

Gen 8, per question. The model's own words are a rounding error.

Output is 1.3k of 511k. Cost is not driven by how much the model says — it is driven by how many times it re-reads the conversation.

What actually drives it

Tool rounds per question against tokens per question, one dot per run.

Each tool round re-reads the whole context, so cost ≈ rounds × context size. One round saved is roughly 50k tokens saved.

What is actually in the 48.7k

Measured on a gen-8 subject, request by request. The base arrives before any project content loads at all.

Every markdown file this project wrote is 6.2k of it — 13%. Deleting the lot would save an eighth of the context and cost the accuracy the docs bought. The 37.8k base is the subagent system prompt, tool definitions, a 25-skill listing and 100+ deferred tool names — mostly harness, and smaller in a real user session than in this eval rig.
