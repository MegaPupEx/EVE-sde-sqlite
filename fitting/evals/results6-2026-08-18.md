Owner directive after run 5 (Fable, xhigh effort) consumed the account's
session budget: evals run on **Sonnet** from now on. Run 6 re-ran the
identical 20-subject × 3-turn protocol — T1 prompts byte-identical
(extracted from the run-5 transcripts), same follow-ups, same two arms —
with subjects on `claude-sonnet-5` (reasoning effort inherited from the
session; the Agent tool can override model but not effort). Graded against
the **corrected** keys in `questions5.md`. The run-5 doc fixes (traps.md

the in-session MCP server still predates the code fixes, so it prints the
old raw cap shape — which made run 6 a clean test of whether the *doc* fix
alone kills the cap-flatten.

Same PASS rate within noise, different failure *shape*: Fable's tail was
misreadings that stayed hedged; Sonnet's tail includes three confident
wrong answers, all the same species — **an unverified game-knowledge
assertion (or an engine artifact taken at face value) where the engine or
data could have arbitrated**. Every run-5 systematic miss came back clean:
the doc fixes transferred.

## What run 6 actually measured

**Sonnet matches Fable on engine-driven turns.** Everywhere the answer
came out of a tool call — stacking chains, spool band, applied-dps honest
zero, structure math, mode sigs, gyro marginals, layout-preserving edits,
versus duels — Sonnet was key-exact, and occasionally sharper than run 5:
it caught the Vedmak using 1 of 4 turret hardpoints (both arms,
independently), applied the always-on cap convention symmetrically in the
duel (run 5's arms only clocked the Punisher), and engine-demoed the
burst-stacking answer instead of asserting it.

**Sonnet's failure signature is confident folklore.** The three FAILs and
most PARTIALs share one anatomy: a game-knowledge claim stated without
letting the engine arbitrate — storm read from raw (sign-inverted) SDE
attributes instead of `set_env`; mutaplasmid applicability asserted
instead of just trying the import; fighter tube/squadron facts invented
instead of read; a recall-driven hull list that forgot the Heron; the
engine's fictional two-prop-mod panel taken at face value. Fable at xhigh
checked itself more; Sonnet needs the skill to force the check. Notably,
each miss was *cheap to catch* — one tool call — which is exactly what
the new doc lines mandate.

**The l2-only arm degrades honestly but pays a completeness tax.** Same
as run 5 (Glorified-tier miss), now in two more places (Heron; mutaplasmid
applicability). The engine's own bundled db could have answered all three;
SKILL.md now says so explicitly.

## Fixes landed this run

- `traps.md` **T18** (new): one prop mod runs per ship
  (`maxGroupActive=1`); the headless engine will happily compute a
  fictional both-active panel — say so, never quote it.
- `traps.md` **T15**: mutaplasmid *applicability* is data — faction
  modules are mutable; try the import, the engine accepts/clamps.
- `traps.md` **T9**: fighter tube class/count and squadron size are
  engine data, never recall; unexplained `amount` overrides flagged.
- `traps.md` **T1**: beacons are quoted only from a `set_env` diff on a
  fitted hull — raw SDE attrs have inverted resonance signs, and
  bare-hull diffs hide rep/cap effects.
- `SKILL.md`: when layer 1 is absent, enumeration questions go to the
  engine's own db, not recall.
- `fitting/engine/eft.py`: a drone line without `xN` (common on
  hand-typed mutated drones) now imports as one drone instead of dying
  in the module branch with eos's opaque "Passed item is not a Module"
  (full/fr3 hit this live; smoke test added).

## Verdict

For the owner's product target (their own chats run Fable at medium
effort; Sonnet is the affordable eval floor): the stack holds at the
Sonnet floor — 85% clean PASS on brand-new-phrasing turns, all engine
math right, degradation honest — and its residual risk is precisely
characterized: **unverified-folklore assertions on the game-knowledge
fringe, at ~5% of turns**, each now targeted by a doc line that converts
the assertion into a one-call check. A stack that survives Sonnet's
lower self-checking discipline should only tighten on Fable-mid.
